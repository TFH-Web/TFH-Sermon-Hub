# TFH-533 search integration verification

Branch: givin-sprint8/integration

## Implemented behavior

- Both `/ai-search` and `/ai-search/results` use the shared API request.
- Requests include query, filters, page and pageSize. Paginated API envelopes
  use server totals; legacy array responses retain compatibility pagination.
- Query/filter/page URL state survives reload and Back/Forward. New searches
  and filters reset pagination; cancelled old requests cannot replace results.
- Cards display returned metadata/snippets and highlight query terms.
- Loading, empty results, errors and Retry remain covered by browser tests.
- A result with a real chunk, validated video and valid source range navigates
  to `/sermons/<sermonId>?t=<start_sec>`, preserving fractional seconds and zero.
- Metadata-only results and unavailable/invalid video sources open the sermon
  without inventing a timestamp. Chat receives only the sermon ID.
- Scores are ranking weights, never displayed as confidence percentages.

## Automated evidence

- Frontend unit suite: 466 passed.
- TypeScript / production build: passed.
- Full Chromium browser suite: 103 passed.
- Real Flask integration smoke: 1 passed, including persisted API search data
  followed through a card to the sermon route at `t=75.5`.
- Source mapping unit cases include missing/invalid ranges, metadata-only
  records, mismatched IDs, fractional timestamps and zero.
- Both search routes cover timed and untimed navigation; delayed-query
  regression coverage verifies older results do not replace newer results.

The Flask smoke uses a temporary database and controlled provider fixtures.
Its external YouTube requests are blocked. Player seeking is exercised with
the transcript browser player mock; these checks do not establish live YouTube
availability, production relevance quality or deployed staging acceptance.
