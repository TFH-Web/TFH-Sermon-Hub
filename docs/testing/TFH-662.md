## Ranking

Risk rule: code that writes data or gates by role ranks above code that fetches
or holds state, which ranks above presentational code. Ties were broken by
branch count and by how many other zero-coverage files one test also covers.

The starting list was the 29 files at 0% in
[Vitest baseline on dev](../testing-and-coverage.md#vitest-baseline-on-dev)
(measured on `dev` `bcd7e3e`). `SermonCard` and `SermonImportItem` gained tests
under TFH-629 before this task, so the live list was 27.

## Implementation

New test files, all beside the source they test:

- `src/hooks/useAISearchRequest.test.tsx`: disabled query, envelope passthrough,
  legacy array paging (pages 1 and 2, empty), error without retry, new request
  per page.
- `src/hooks/useAISearch.test.tsx`: reads the address bar (defaults, trimming,
  invalid type and page values, empty `q`), submit (first search, refetch,
  later page, changed query), filters and paging, result mapping, loading,
  failure and retry, Back/Forward.
- `src/modals/AddTagModal.test.tsx`: required field, trimmed POST, cache
  invalidation, 403, 422 field error, 500 fallback, pending state, error
  clearing, Cancel.
- `src/modals/AddSermon.test.tsx`: hidden for non-admins, button for admins,
  opens the upload dialog (stubbed).
- `src/Sermons.test.tsx`: loading shell, request parameters, option order,
  status, topic, speaker, series, sort and page changes, empty state, both
  error states with their Retry behaviour, admin button.
- `src/AISearch.test.tsx`: first search, restore from the address, empty and
  error states, highlight, paging, filters, opening a card and the chat button.
- `src/components/SearchDateDropdown.test.tsx`: trigger labels, presets,
  custom range, check marks, outside clicks.
- `src/Series.test.tsx`, `src/TagsAndMetadata.test.tsx`, `src/Speakers.test.tsx`:
  card or table content, request parameters, paging, empty and error states,
  admin gating on tags, banner hue.

Conventions followed: network is faked by replacing the Axios adapter, no new
packages, no production code changes, no change to `Frontend/vite.config.ts`.
The AI search tests use `BrowserRouter` and `window.history.replaceState`
because `useAISearch` merges filters into `window.location.search`.

## Limitations

- `NewSeriesModal` is a stub: it shows "Series created" and saves nothing.
  Testing it would lock in wrong behaviour, so the `Series` tests stub the
  modal and check only that it opens.
- Dead files (`FilterDropdown`, `SearchResultCard`, `src/data/*.ts`) look
  unused. Deleting them is cheaper than testing them but is a separate cleanup
  that needs an owner.
- `main.tsx` and `authConfig.ts` only matter in Playwright runs; `authConfig.ts`
  builds an MSAL client at import time.
- The Tier 2 pages (`Series`, `TagsAndMetadata`, `Speakers`) rely on the page
  layout and modals being stubbed; their modals are covered separately.
- Left uncovered: `AISearchResults.tsx`, `Notifications.tsx`, `PopularTags.tsx`.

## Bug candidates found while testing (for TFH-667, not fixed here)

- `NewSeriesModal` reports success but never saves.
- `SearchFilters` hard-codes seven speakers instead of using the speakers API.
- `?q=` (empty) counts as a search and sends a request with an empty query
  (pinned by a characterisation test in `useAISearch.test.tsx`).
- `useAISearch.updateParameters` reads `window.location.search` instead of the
  router's state, which makes the hook hard to test under `MemoryRouter`.
